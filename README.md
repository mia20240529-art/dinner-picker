# 今晚吃什么

手机优先的两人份晚餐选择器。纯 HTML、CSS 和 JavaScript，无后端、数据库、登录或第三方前端依赖。

## 本地使用

已安装 Node.js 的电脑，在本目录运行 `npm start`，访问 http://127.0.0.1:4173 。也可用任何静态 HTTP 服务器托管 `dist` 文件夹。

不要直接双击 HTML：浏览器通常禁止通过 `file://` 加载 JSON 和 JavaScript 模块。网页正常部署后不需要服务器端程序。

## 文件结构

- `dist/index.html`：页面与弹窗容器。
- `dist/css/style.css`：暖白、墨绿主题和手机适配。
- `dist/js/app.js`：页面操作、菜谱、历史和收藏。
- `dist/js/engine.js`：搭配约束、模式、权重和时间估算。
- `dist/js/storage.js`：持久化、数据校验和失败回退。
- `dist/data/dishes.json`：58道独立菜谱；31道可作主菜、14道可作配菜、13道汤、1份米饭，番茄炒蛋可作两种角色但不重复记录。
- `serve.mjs`：仅用于电脑本地预览的静态服务器。
- `tests/engine.test.mjs`：菜库、搭配、换菜、权重与存储测试，运行 `npm test`。

## 功能与规则

自选主菜、随机搭配、清淡模式、快速模式、换主菜/配菜/汤、整套重抽、菜谱详情、收藏及收藏优先、最近吃过和确认今晚菜单均已实现。

浓口或偏油主菜必须配清淡配菜与汤；西兰花主菜不重复搭配西兰花。相同菜不能同时占两个角色。共享食材降低搭配权重，豆腐重复再额外降低。炖菜默认不另做汤，保留可选汤卡片，可勾选加入。淀粉菜会提示适量减少米饭，不会取消米饭。

快速模式按“各道菜依次制作的耗时之和”与“电饭煲快煮约25分钟”取较大值，限制在30分钟内。普通电饭煲程序、操作熟练度和火力会改变实际时间。若单独换菜在该模式下无解，会提示用户整套重抽；不会悄悄突破时间限制。手动选择不符合当前模式的主菜会提示并切回家常模式。

换主菜会尽量保留原配菜和汤，只替换不兼容的部分。换配菜或汤保留其他菜；换汤意味着本餐加入这道汤。

`localStorage` 键为 `dinner-for-two:v1`，保存当前菜单、最近3次生成结果、最多60次确认的用餐记录、收藏ID及收藏优先设置。最近3次推荐与确认记录降低再次推荐权重。同一天重复确认相同套餐不会重复记账。记录只保存在当前浏览器和网址下，不会跨设备同步；清除浏览器数据会删除记录。存储被禁用时页面仍可使用，并提示无法保存。

## 分享当前菜单

菜单卡片上方的分享区域可以复制当前菜单文字，或生成只包含菜品 ID 的分享链接。链接使用 `main`、`side`、`soup`、`staple` 查询参数，示例：`?main=beef_green_pepper&side=lotus_slices&soup=luffa_egg_soup&staple=rice`。链接不依赖数据库，打开后会直接显示对应菜单，每道菜仍可查看菜谱，也可以继续换菜或整套重抽。

支持 Web Share API 的手机浏览器会显示“分享给朋友”；其他浏览器可复制链接。分享链接中的未知菜品会被忽略并用当前菜库自动补齐，同时提示“这是朋友分享的菜单”。

## 增删菜品

直接编辑 `dist/data/dishes.json`。每项包含唯一 `id`、`name`、`category`、`category_label`、默认 `role`、可用 `roles`、`servings: 2`、`time`（分钟）、`difficulty`、`light`、`oily`、`starchy`、`brothy`、`ingredients`、`seasonings`、`steps`、`tags`、`avoid_pair_tags`、`substitutions`、`note`。

`roles` 可为 `main`、`side`、`soup`、`staple`。`brothy` 标记汤汁丰富的主菜；`tags` 使用具体主要食材标签，用于避免重复搭配。叶菜统一用“叶菜”标签，具体可选品种列在替换食材里。配菜中的包菜、土豆、莲藕等仍保留具体菜名。

永久排除的食材不能写入食材、调料、步骤、替换食材或备注。加载时会校验已知禁用词并拒绝不合规菜库；新增菜谱仍需人工检查食材别名。

## GitHub Pages

`dist` 即完整可发布目录，不需要构建。把 `dist` 内的 `index.html`、`css`、`js`、`data` 上传到 GitHub 仓库发布根目录，然后用 GitHub Pages 发布该目录即可。全部资源使用相对路径，兼容仓库子路径。也可以通过 Pages 自定义工作流直接上传 `dist`。

Sites 配置单独放在 `.openai/hosting.json`，与网页运行无关。GitHub Pages 只需要 `dist` 的内容，网页自身没有账号系统。

## 验证范围

自动化检查覆盖菜库完整性、禁用食材、数百轮随机/清淡/快速推荐、单独换菜、炖菜可选汤、收藏与历史权重、存储损坏及禁用回退；并检查本地资源和 JavaScript 语法。未进行浏览器自动点击或截图验收。

支持时注册读取菜单和生成菜单两个 WebMCP 工具，普通浏览器无需支持该提案。当前环境未提供相应的真实 WebMCP 验证上下文，该可选接口未进行真实浏览器合同验证。
